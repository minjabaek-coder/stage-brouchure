# 01 · 제품 개요

> 기준 문서: [`00-prd.md`](./00-prd.md) v1.1

## 1. 배경

(사)한국예술가곡총연합회는 2026년 어울림 콘서트를 송파문화예술회관에서 개최한다. 운영팀이 그동안 겪은 문제는 다음과 같다.

- 사전 안내문(PDF/이미지)을 메신저로 배포 → 참석자가 잃어버리거나 못 받음
- 행사 당일 입구에서 좌석표(종이) 줄서기 → 혼잡과 지연
- 좌석 배치 변경이 잦아 인쇄물이 자주 무용지물
- 디자인 외주 비용 부담

첫 단계로 단일 HTML 페이지(`docs/assets/reference-original.html`) 시안을 검증했고, 이를 운영 가능한 웹앱으로 발전시킨다.

## 2. 비전 (Vision)

> 참석자는 휴대폰만 있으면 본인 좌석을 즉시 확인할 수 있고,  
> 운영자는 코드를 모르고도 명단·이미지를 직접 업로드할 수 있는  
> **단순하고 안정적인 디지털 콘서트 안내장**.

## 3. 핵심 가치 제안

| 사용자 | 현재 (정적 HTML) | 웹앱 전환 후 |
|--------|-----------------|--------------|
| 참석자 | 이름 검색 후 SVG 좌석 확인 | + 이름+전화4자리 보안 검색, 정적 좌석맵 이미지, 8장 브로셔 열람 |
| 운영자 | 코드 수정 + 재배포 필요 | `/admin` 단일 페이지에서 CSV·이미지 업로드만으로 운영 |

## 4. 사용자 페르소나 (PRD §1.2)

### Persona A · 일반 관객 (약 500–700명)
- 50–70대 음악 애호가 + 30–40대 가족 동반
- 디바이스: 모바일 우선 (iOS/Android 거의 반반)
- 행동 특성: 카카오톡으로 받은 링크 한 번 탭 → 빠르게 본인 좌석 확인 후 닫음
- 핵심 필요: **이름 + 전화번호 뒷자리 4자리 입력 한 번이면 끝.** 회원가입·로그인 없음

### Persona B · 운영자 (1명)
- 40–60대, 엑셀에 익숙하지만 개발 도구는 낯섦
- 디바이스: PC 위주, 행사 당일은 모바일 병행
- 행동 특성: 게스트 명단을 엑셀로 정리 → CSV 로 내보내기
- 핵심 필요: **`/admin` 접속 → CSV 업로드 한 번으로 명단 반영**, 좌석배치도/브로셔 이미지 교체

## 5. 핵심 사용 시나리오

### 시나리오 1 · 행사 당일 참석자 좌석 확인 (PRD §5.2)
1. 참석자가 카카오톡으로 받은 링크 또는 입구 QR 을 스캔하여 메인 페이지 접속
2. (선택) 초대 영상 시청
3. **자리 찾기** 메뉴 탭
4. 본인 이름 + 전화번호 뒷자리 4자리 입력 → "자리 확인"
5. 결과 카드에 **이름 / 마스킹된 전화 / 좌석번호** 표시
6. 페이지 하단에 항상 표시되는 **정적 좌석배치도 이미지**로 위치 확인 (핀치줌 가능)

### 시나리오 2 · 사전 브로셔 열람
1. 참석자가 행사 1주 전 알림으로 링크 수신
2. 홈에서 **브로셔** 탭
3. 8장의 브로셔 이미지를 세로 스크롤로 열람 (페이지 번호 1/8 ~ 8/8 표시)
4. 이미지 탭으로 풀스크린 확대

### 시나리오 3 · 운영자 사전 준비 (PRD §5.1)
1. 운영진이 티켓 신청자 명단을 구글 시트로 정리
2. 좌석 배치 결정 후 명단에 좌석번호 부여
3. CSV (name, phone_last4, seat, note) 로 내보내기
4. `/admin` 접속 → CSV 업로드 → 미리보기 확인 → 덮어쓰기
5. 좌석배치도 이미지 1장 업로드
6. 브로셔 이미지 8장 일괄 업로드 → 순서 확인 → 업로드
7. 본인 이름으로 검색 테스트 → 정상 동작 확인
8. 행사 페이지 링크를 QR 로 만들어 배포

### 시나리오 4 · 행사 직전 명단 수정 (PRD §5.3)
1. 운영진이 원본 시트에서 좌석 변경
2. 수정된 CSV 재업로드 (전체 덮어쓰기, 직전 데이터 자동 백업)
3. 변경 즉시 반영, 참석자가 새로고침하면 새 좌석 표시

## 6. 비기능 요구사항 (NFR)

| ID | 항목 | 목표 |
|----|------|------|
| NFR-01 | 모바일 우선 | 320–768px 폭 완벽 지원, 데스크톱은 중앙 정렬 카드 형태 |
| NFR-02 | 한국어 UI | 모든 라벨/메시지 한국어, 영문은 보조 표기 |
| NFR-03 | 첫 로딩 | 2초 이내 (3G 환경에서도 3초 이내) — PRD §4.3 |
| NFR-04 | 좌석 검색 응답 | 1초 이내 — PRD §4.3 |
| NFR-05 | 브로셔 이미지 로딩 | 첫 이미지 1초 이내, 나머지는 Lazy Load — PRD §4.3 |
| NFR-06 | 동시 접속 | 최소 100명 동시 사용 가능 — PRD §4.3 |
| NFR-07 | HTTPS | 필수 — PRD §4.4 |
| NFR-08 | 검색 Rate Limit | 1분당 30회 이내 (무차별 조회 방지) — PRD §4.4 |
| NFR-09 | 개인정보 최소화 | 전화번호는 **뒷 4자리만** 저장, 전체 번호 저장 금지 — PRD §4.4 |
| NFR-10 | 파일 크기 제한 | CSV 5MB, 이미지 장당 10MB — PRD §4.4 |

## 7. 디자인 컨셉 (PRD §1.3)

- **톤**: 럭셔리 / 클래식 음악회의 격조
- **컬러**: 먹빛 배경 `#0a0a0c` + 와인색 `#5c1a1b` + 골드 `#c5a572`
- **폰트**: Cormorant Garamond (영문 세리프), Noto Serif KR (국문 세리프)
- **반응형**: 모바일 우선 설계, PC도 동일하게 지원

## 8. 성공 지표 (KPI)

- 행사 당일 좌석 검색 완료 비율 ≥ 80% (등록 게스트 대비)
- 입구 좌석 안내 문의(데스크) 건수 50% 이상 감소
- 운영자 명단 수정 평균 소요 시간 ≤ 1분 (CSV 재업로드 1회)

## 9. 다루지 않는 범위 (Out of Scope, PRD §7)

- 티켓 결제 / 발권
- 좌석 선택 (참석자가 직접 좌석을 고르는 기능)
- 회원가입 / 로그인 (일반 사용자용)
- 관리자 로그인 / 권한 관리
- SMS / 알림톡 발송
- 좌석배치도 인터랙티브 기능 (정적 이미지로 충분)
- 브로셔 내용 텍스트 검색
- 다국어 지원 (한국어만)
- 행사 후기 / 댓글 / 후속 콘텐츠
