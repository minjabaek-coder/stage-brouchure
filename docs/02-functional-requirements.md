# 02 · 기능 요구사항 (Functional Requirements)

> 기준 문서: [`00-prd.md`](./00-prd.md) v1.1

본 문서는 어울림콘서트 웹앱의 모든 기능을 **FR-G##** (Guest, 관객용) / **FR-A##** (Admin, 관리자용) 식별자로 명세한다.

PRD v1.1 의 모든 기능은 **P0 (MVP 필수)** 다.

각 FR 형식:

```
### FR-X##  제목                                        (P0)
- 설명: 무엇을 하는가
- 입력: 사용자가 제공하는 것
- 출력: 시스템이 보여주는 것
- 수용 기준 (AC): AC-1 …
- 참고: 관련 화면, 의존 FR, PRD 섹션
```

---

## A. 관객용 기능 (Public · FR-G)

### FR-G01  메인 페이지                                                 (P0)
- 설명: 첫 진입 시 표시되는 랜딩. 헤더(타이틀·일시·장소·시간), 초청 영상, 두 개의 메뉴(자리찾기·브로셔), 푸터
- 입력: 없음 (URL `/`)
- 출력: 헤더 카드, 영상 썸네일, 메뉴 카드 2개, 푸터
- AC:
  - AC-1 모바일 320px 이상에서 가로 스크롤이 발생하지 않는다
  - AC-2 헤더의 일시·장소·시간은 PRD §1 의 행사 정보로 하드코딩 (단일 행사 전제)
  - AC-3 페이지 진입 시 fadeUp 애니메이션 1회 실행
- 참고: PRD §2.1, 원본 HTML lines 918-1012

### FR-G02  초청 영상 인라인 재생                                       (P0)
- 설명: 헤더 영상 영역. 초기엔 YouTube 썸네일을 표시, 탭 시 iframe 으로 교체하여 자동 재생. 새 창/팝업 금지
- 입력: YouTube 비디오 ID (`0aT4IdHXZW8`, `assets.video_youtube_id` 또는 환경변수)
- 출력: 썸네일 → 클릭 시 자동재생 iframe (페이지 내 인라인)
- AC:
  - AC-1 첫 진입 시 iframe 미로드, LCP 영향 없음
  - AC-2 썸네일 로딩 실패 시 `hqdefault.jpg` 로 대체
  - AC-3 모바일 `playsinline` 으로 인라인 재생, 새 창으로 리다이렉트 금지
- 참고: PRD §2.1, 원본 HTML lines 943-963

### FR-G03  자리 찾기 — 이름 + 전화번호 뒷4자리 검색                    (P0)
- 설명: 게스트의 이름과 전화번호 뒷 4자리를 **AND 조건** 으로 일치할 때만 본인 좌석 정보를 조회. 보안 의도: 동명이인 노출 방지 + 타인 좌석 무단 조회 차단
- 입력:
  - 이름 (텍스트, trim, 공백 제거 후 정확 일치)
  - 전화번호 뒷 4자리 (숫자 4자리, maxlength=4)
- 출력: 결과 카드 (이름 / 마스킹된 전화 / 좌석번호) 또는 실패 메시지
- AC:
  - AC-1 두 필드 중 하나라도 비면 "이름과 전화번호 뒷자리 4자리를 모두 입력해 주세요." 안내
  - AC-2 `phone_last4` 가 4자리 숫자가 아니면 입력 단계에서 거부
  - AC-3 매칭 성공 시 결과 카드 표시 (이름, `****-****-1234`, 좌석번호)
  - AC-4 매칭 실패 (이름·전화 어느 쪽이 틀려도) 시 동일한 메시지 "일치하는 정보를 찾을 수 없습니다. 입력 정보를 확인해 주세요." (보안상 원인 미특정)
  - AC-5 검색 입력값을 비우면 결과 카드가 사라진다
- 참고: PRD §2.2.3, §2.2.5

### FR-G04  자리 찾기 — 정적 좌석배치도 표시                            (P0)
- 설명: 자리 찾기 페이지 하단에 운영자가 업로드한 좌석배치도 **이미지** 1장을 항상 표시. 인터랙티브 기능 없음
- 입력: `assets.seat_map.url`
- 출력: 이미지 (`<img>` 또는 `next/image`)
- AC:
  - AC-1 검색 결과와 무관하게 항상 노출
  - AC-2 모바일에서 핀치줌·확대보기 가능 (브라우저 기본 또는 가벼운 라이트박스)
  - AC-3 이미지 미업로드 상태일 때는 "좌석배치도 준비 중" 플레이스홀더 표시
  - AC-4 이미지 alt: "어울림콘서트 좌석 배치도"
- 참고: PRD §2.2.2.5

### FR-G05  자리 찾기 — 검색 Rate Limit                                 (P0)
- 설명: 무차별 조회 방지. 1분당 30회 이내 (PRD §4.4)
- 입력: 클라이언트 IP (또는 세션 쿠키)
- 출력: 30회 초과 시 HTTP 429 + "잠시 후 다시 시도해 주세요" 안내
- AC:
  - AC-1 `@upstash/ratelimit` 또는 단순 in-memory 카운터로 구현
  - AC-2 정상 사용자(행사 당일 한 번 검색)는 절대 걸리지 않는 임계치
- 참고: PRD §4.4

### FR-G06  브로셔 — JPG 8장 세로 스크롤 열람                           (P0)
- 설명: 운영자가 업로드한 브로셔 이미지 8장을 위에서 아래로 순서대로 표시. 페이지 번호(1/8 ~ 8/8) 표기
- 입력: URL `/brochure`, `assets.brochure_01..brochure_08`
- 출력: 8개 이미지 + 각 이미지 위/아래 페이지 번호 표기 + 골드 ornament 구분선
- AC:
  - AC-1 8장 모두 세로 스크롤로 연속 표시 (캐러셀·썸네일 그리드 아님)
  - AC-2 첫 이미지 1초 이내 로드, 나머지는 Lazy Loading (`loading="lazy"`)
  - AC-3 모바일에서 이미지 탭 시 풀스크린 확대 (라이트박스)
  - AC-4 8장보다 적게 업로드된 경우 업로드된 만큼만 표시 (빈 슬롯은 숨김)
  - AC-5 이미지 미업로드 상태일 때 "브로셔 준비 중" 안내
- 참고: PRD §2.3

### FR-G07  자리 찾기 / 브로셔 페이지 진입·복귀                         (P0)
- 설명: 메인의 메뉴 카드에서 자리찾기·브로셔로 이동, 헤더의 뒤로가기 버튼으로 메인 복귀
- 입력: 메뉴 카드 클릭 / 뒤로가기 버튼
- 출력: 라우트 전환 + (선택) 슬라이드 트랜지션
- AC:
  - AC-1 브라우저 뒤로가기와 헤더 ← 버튼이 동일하게 동작
  - AC-2 자리찾기 페이지 이탈 시 검색 입력값과 결과 카드 초기화
- 참고: PRD §2.2.2, §2.3.2

### FR-G08  모바일 반응형                                               (P0)
- 설명: 320px ~ 768px 까지 1열 카드, 768px 이상은 중앙 정렬 (최대 폭 560px)
- AC:
  - AC-1 320px iPhone SE 에서 헤더·메뉴·좌석맵·브로셔 모두 잘리지 않음
  - AC-2 다크 모드와 무관하게 의도된 잉크/페이퍼 톤 유지
- 참고: PRD §1.3, 원본 HTML lines 899-910

## B. 관리자 기능 (Admin · FR-A)

> `/admin` 접근에 **인증 없음** (PRD §3.1). 운영자 1인 단독 사용. URL 비공개로 보호 (Security by Obscurity).

### FR-A01  관리자 단일 페이지 진입                                     (P0)
- 설명: `/admin` (또는 `/admin-h7k9x2` 같은 추측 어려운 경로) 접속 시 로그인 없이 즉시 단일 관리 페이지를 표시. 세 가지 업로드 섹션을 한 화면에 배치
- 입력: URL 직접 진입
- 출력: 3 섹션 (CSV / 좌석배치도 이미지 / 브로셔 이미지 8장)
- AC:
  - AC-1 인증·미들웨어 없음
  - AC-2 URL 은 `robots.txt` 에서 disallow, sitemap 미포함
  - AC-3 화면 상단에 현재 등록 게스트 수 + 마지막 업로드 일시 표시
- 참고: PRD §3.1, §3.2

### FR-A02  좌석 명단 CSV 업로드 (전체 덮어쓰기)                        (P0)
- 설명: CSV 파일을 업로드하면 기존 명단을 전부 삭제하고 새 데이터로 교체. 직전 데이터는 자동 백업
- 입력: CSV 파일 (UTF-8 또는 EUC-KR)
- CSV 컬럼 (PRD §3.3.2):
  - `name` (필수, string)
  - `phone_last4` (필수, 4자리 숫자 string)
  - `seat` (필수, string · 예: "A-2")
  - `note` (선택, string)
- 출력: 미리보기 (상위 5–10행) → 사용자 확인 → "총 N건 등록 완료" 토스트
- AC (PRD §3.3.3 검증 규칙):
  - AC-1 필수 컬럼 누락 시 업로드 거부 + 오류 메시지
  - AC-2 `phone_last4` 가 4자리 숫자가 아닌 행은 무시 + 오류 목록 표시
  - AC-3 `(name, phone_last4)` 중복은 마지막 행으로 덮어씀
  - AC-4 빈 행은 무시
  - AC-5 인코딩 오류 시 UTF-8/EUC-KR 자동 감지 시도, 실패 시 안내
  - AC-6 업로드 직전 "기존 데이터가 모두 삭제되고 새 데이터로 교체됩니다" 경고 모달
  - AC-7 업로드 시 직전 데이터를 자동 백업 (최근 3개 버전 유지) — PRD §3.3.4
  - AC-8 파일 크기 5MB 초과 시 거부 — PRD §4.4
- 참고: PRD §3.3, 라이브러리: Papaparse

### FR-A03  좌석배치도 이미지 업로드                                    (P0)
- 설명: 단일 이미지 1장을 업로드, 기존 이미지 자동 교체
- 입력: 이미지 파일 (JPG, PNG)
- 출력: 업로드 후 미리보기
- AC:
  - AC-1 지원 포맷: JPG, JPEG, PNG
  - AC-2 권장 크기: 가로 1200px 이상
  - AC-3 파일 크기 5MB 이하 (PRD §3.4)
  - AC-4 업로드 시 기존 이미지 자동 교체 (덮어쓰기)
  - AC-5 자동 최적화: 가로 1600px 리사이즈, JPG 80% 압축 (선택)
  - AC-6 `assets.seat_map` 키로 저장
- 참고: PRD §3.4

### FR-A04  브로셔 이미지 업로드 (8장)                                  (P0)
- 설명: 한 번에 8장을 일괄 업로드하거나, 페이지별 개별 교체. 파일명 오름차순 자동 정렬
- 입력: 이미지 파일 1–8장
- 출력: 격자(grid) 미리보기 (8개 슬롯), 순서 확인 후 업로드
- AC:
  - AC-1 지원 포맷: JPG, JPEG, PNG
  - AC-2 최대 매수 8장. 8장 초과 시 거부
  - AC-3 장당 최대 10MB (PRD §3.5.2)
  - AC-4 자동 최적화: 가로 1600px 리사이즈, JPG 80% 압축 (PRD §2.3.4, §3.5.2)
  - AC-5 파일명 오름차순 자동 정렬, 사용자가 드래그로 순서 변경 가능
  - AC-6 [방식 A] 일괄 업로드: 새로 업로드 시 8장 전체 교체
  - AC-7 [방식 B] 개별 교체: 페이지 슬롯별로 1장씩 교체 (예: 3페이지만)
  - AC-8 `assets.brochure_01` ~ `assets.brochure_08` 키로 저장
- 참고: PRD §3.5
