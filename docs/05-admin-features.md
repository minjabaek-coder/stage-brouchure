# 05 · 관리자 기능 (Admin Features)

> 기준 문서: [`00-prd.md`](./00-prd.md) v1.2 · §3

운영자 1인이 코드를 모르고도 행사를 운영할 수 있도록 하는 관리 페이지 명세. 관리자 영역은 두 페이지로 분리됨:

- `/admin` — 콘텐츠 관리 (CSV / 좌석배치도 / 브로셔)
- `/admin/messages` — 응원 메시지 모더레이션 (목록 + 삭제)

두 페이지는 상단의 `AdminNav` 탭으로 전환한다.

## 0. 진입과 권한 (PRD §3.1)

- **URL**: `/admin` 및 `/admin/messages` (운영상 추측 어려운 경로 권장: `/admin-h7k9x2`, `/admin-h7k9x2/messages` 등 — `ADMIN_PATH_SUFFIX` 환경변수 + `middleware.ts` rewrite 로 처리)
- **인증 없음** — 운영자 1인 단독 사용 전제
- **보안 권고**:
  - URL 을 외부에 공개하지 않음
  - `robots.txt` 에서 `/admin*` disallow
  - sitemap 에 미포함
  - HTTPS 필수 (NFR-07)
- 향후 다중 사용자가 필요해지면 PRD 갱신을 통해 인증 도입을 재논의한다.

## 1. SCR-A01 · 단일 관리 페이지 (`/admin`)

### 1.1 화면 구성 (PRD §3.2)

세 가지 업로드 영역을 한 화면에 세로로 배치.

```
┌─────────────────────────────────────────┐
│  관리자 페이지                           │
│  현재 등록: 547명                        │
│  마지막 업데이트: 2026-05-25 18:30       │
├─────────────────────────────────────────┤
│  [1] 좌석 명단 (CSV)                     │
│      [CSV 파일 선택]  [업로드]            │
├─────────────────────────────────────────┤
│  [2] 좌석 배치도 (이미지 1장)            │
│      [현재 이미지 미리보기]              │
│      [이미지 선택]  [업로드]              │
├─────────────────────────────────────────┤
│  [3] 브로셔 이미지 (8장)                 │
│      [페이지 1] [페이지 2] ... [페이지 8]│
│      [이미지 8장 일괄 업로드]            │
│      또는 [개별 업로드]                  │
└─────────────────────────────────────────┘
```

### 1.2 상단 상태 정보

- 현재 등록 게스트 수 (`attendees` count)
- 마지막 명단 업로드 일시 (`max(updated_at)` from `attendees`)
- 마지막 좌석맵 업로드 일시
- 마지막 브로셔 업로드 일시 (가장 최근 `brochure_*` updated_at)

## 2. 섹션 [1] · 좌석 명단 CSV 업로드

### 2.1 업로드 흐름 (PRD §3.3.1)

1. 관리자가 CSV 파일 준비 (구글 시트/엑셀에서 CSV 내보내기)
2. "CSV 파일 선택" → 파일 선택
3. **미리보기** (상위 5–10행) 노출
4. "이 데이터로 덮어쓰기" 확인 모달
5. 기존 데이터 전체 교체 (overwrite) + 직전 데이터 자동 백업
6. 업로드 결과 토스트: "총 N건 등록 완료" + 오류 행 안내

### 2.2 CSV 포맷 (PRD §3.3.2)

| 컬럼 | 필수 | 타입 | 예시 | 설명 |
|------|------|------|------|------|
| `name` | ✓ | string | 홍길동 | 참석자 이름 |
| `phone_last4` | ✓ | string(4) | 1234 | 전화번호 뒷 4자리 (숫자) |
| `seat` | ✓ | string | A-2 | 좌석번호 |
| `note` | ✗ | string | 임원석 | 비고 |

예시:
```csv
name,phone_last4,seat,note
신귀복,1234,A-1,이사장석
정희준,5678,A-2,명예이사장석
홍길동,9012,B-5,
```

### 2.3 검증 규칙 (PRD §3.3.3)

| 검증 | 처리 |
|------|------|
| 필수 컬럼 누락 | 업로드 거부 + 오류 메시지 |
| `phone_last4` 가 4자리 숫자가 아님 | 해당 행 무시 + 오류 목록 표시 |
| 동일 (이름 + 전화번호) 중복 | 마지막 행 기준으로 저장 |
| 빈 행 | 무시 (skip) |
| 인코딩 오류 (한글 깨짐) | UTF-8 / EUC-KR 자동 감지 시도, 실패 시 안내 |
| 파일 크기 5MB 초과 | 거부 (NFR-10) |

### 2.4 자동 백업 (PRD §3.3.4)

- CSV 업로드 직전 기존 `attendees` 전체를 CSV 로 직렬화하여 Supabase Storage `backups/<timestamp>.csv` 에 저장
- `csv_backups` 테이블에 메타 기록
- 최근 3개 버전만 유지 (4번째 업로드 시 가장 오래된 백업 자동 삭제)

### 2.5 부분 수정 UI 미제공

PRD §3.3.4 명시: 부분 수정 UI 없음. 수정도 동일하게 CSV 전체 교체 방식으로 단순화.

## 3. 섹션 [2] · 좌석배치도 이미지 업로드 (PRD §3.4)

- **단일 이미지 1장** 업로드
- 지원 포맷: JPG, PNG
- 권장 크기: 가로 1200px 이상
- 파일 크기 5MB 이하 (NFR-10)
- 업로드 시 기존 이미지 자동 교체 (`assets.seat_map` UPSERT)
- 업로드 후 미리보기 표시
- (선택) 자동 최적화: `sharp` 로 가로 1600px 리사이즈 + JPG 80% 압축

## 4. 섹션 [3] · 브로셔 이미지 업로드 (8장) (PRD §3.5)

### 4.1 두 가지 업로드 방식

**방식 A · 일괄 업로드**
- "브로셔 이미지 선택" 클릭 → 파일 선택창에서 8장 모두 선택
- 파일명 오름차순 자동 정렬 (예: `01.jpg, 02.jpg, ... 08.jpg`)
- 격자 미리보기로 순서 확인
- 필요 시 드래그(또는 위/아래 화살표)로 순서 변경
- "업로드" → 8장 모두 저장 (`brochure_01` ~ `brochure_08`)

**방식 B · 개별 업로드 (수정용)**
- 각 페이지 슬롯(1~8) 표시
- 슬롯 클릭 → 단일 파일 선택 → 해당 슬롯만 교체

### 4.2 처리 규칙 (PRD §3.5.2)

| 항목 | 사양 |
|------|------|
| 지원 포맷 | JPG, JPEG, PNG |
| 최대 매수 | 8장 (8장 초과 시 거부, 미만은 허용) |
| 장당 최대 용량 | 10MB (NFR-10) |
| 자동 최적화 | 가로 1600px 리사이즈, JPG 80% 압축 |
| 순서 | 파일명 오름차순 자동 정렬 → 수동 재배치 가능 |
| 기존 이미지 | 새 일괄 업로드 시 8장 전체 교체 |

### 4.3 미리보기 (PRD §3.5.3)

업로드 전 8장의 썸네일을 격자(grid)로 표시, 페이지 번호 매김.

```
┌──────┬──────┬──────┬──────┐
│  1   │  2   │  3   │  4   │
└──────┴──────┴──────┴──────┘
┌──────┬──────┬──────┬──────┐
│  5   │  6   │  7   │  8   │
└──────┴──────┴──────┴──────┘
[순서가 맞으면 "업로드" 클릭]
```

## 5. SCR-A02 · 응원 메시지 관리 (`/admin/messages`)

### 5.1 화면 구성 (PRD §3.6)

```
┌─────────────────────────────────────────┐
│  [AdminNav]                              │
│  [콘텐츠 관리]  [응원 메시지 관리 ●]     │
├─────────────────────────────────────────┤
│  응원 메시지 관리                        │
│  관객이 보낸 응원 메시지를 확인하고      │
│  부적절한 글은 삭제합니다.               │
│  총 N개의 메시지                         │
├─────────────────────────────────────────┤
│  ┌──────────────────────────┐            │
│  │ 닉네임 · 12분 전          │ [삭제]    │
│  │ 본문 ... (여러 줄 가능)   │            │
│  └──────────────────────────┘            │
│  ┌──────────────────────────┐            │
│  │ ...                       │            │
│  └──────────────────────────┘            │
└─────────────────────────────────────────┘
```

### 5.2 삭제 흐름 (PRD §3.6.2)

1. 카드의 "삭제" 버튼 클릭
2. `ConfirmDialog` 노출 ("이 메시지를 삭제할까요? 되돌릴 수 없습니다.")
3. 확인 시 `DELETE /api/admin/messages/[id]` 호출
4. 성공 응답 후 sonner 토스트 "메시지를 삭제했습니다."
5. 서버 라우트 핸들러가 `revalidatePath('/')` + `revalidatePath('/messages')` 호출 → 홈 미리보기, 공개 목록 즉시 갱신
6. 클라이언트가 `router.refresh()` 로 `/admin/messages` 자체도 갱신

### 5.3 정책 (단순화)

- **일시 비공개·복구 미지원**: hard delete 만, soft delete 컬럼 없음
- **신고(report) 기능 없음**: 운영자가 직접 목록을 훑어 판단
- **본인 작성자 삭제 미지원**: 작성자는 IP/이메일을 남기지 않으므로 식별 불가
- **목록 페이지네이션 없음**: `getAllMessages()` 가 최대 100건만 반환 (행사 1회 단발성 전제)

### 5.4 e2e 정책

- `/admin/messages` 는 데스크톱 운영자 전용 흐름이므로 Playwright 의 `mobile-chromium` 프로젝트에서는 admin 테스트를 skip 한다 (`tests/e2e/messages.spec.ts`)

## 6. 공통 UI 패턴

- **저장 토스트**: 우상단 `sonner` (성공 녹색, 실패 빨간색)
- **확인 모달**: 덮어쓰기·삭제 등 비가역 작업 (예: "기존 데이터가 모두 삭제되고 새 데이터로 교체됩니다")
- **빈 상태 (Empty State)**: 자산 미업로드 상태에서는 "아직 업로드된 이미지가 없습니다" 가이드
- **로딩**: 업로드 중 spinner + 진행률 (대용량 일괄 업로드)
- **오류 표시**: CSV 검증 실패 행은 행 번호 + 사유를 인라인으로 표기

## 7. 운영 체크리스트 (PRD §5.1, 행사 D-7 ~ D-1)

- [ ] 운영진이 티켓 신청자 명단을 구글 시트로 정리
- [ ] 좌석 배치 결정 후 명단에 좌석번호 부여
- [ ] CSV 형식으로 내보내기
- [ ] `/admin` 접속 → CSV 업로드 → 미리보기 → 확인 → 덮어쓰기
- [ ] 좌석배치도 이미지 업로드
- [ ] 브로셔 이미지 8장 일괄 업로드 → 순서 확인 → 업로드
- [ ] 본인 이름 + 전화 4자리로 검색 테스트 → 정상 동작 확인
- [ ] 브로셔 페이지에서 8장 모두 정상 표시 확인
- [ ] 행사 페이지 링크를 QR 코드로 만들어 안내 자료에 포함

## 8. 행사 당일·직후 시나리오

- **명단 수정** (PRD §5.3): 운영진이 원본 시트 수정 → 수정된 CSV 재업로드 (전체 교체) → 즉시 반영
- **브로셔 수정** (PRD §5.4): `/admin` 접속 → 수정할 페이지 슬롯 클릭하여 개별 교체, 또는 8장 전체 재업로드
- **좌석배치도 수정**: 새 이미지 업로드 → 즉시 반영
- **응원 메시지 모더레이션** (PRD §3.6): 행사 D-1 부터 행사 종료 시점까지 운영자가 주기적으로 `/admin/messages` 를 확인, 부적절한 글이 보이면 삭제. 행사 종료 후에도 메시지는 유지되며, 다음 회차 사이트로 이관할지 폐기할지는 별도 판단
