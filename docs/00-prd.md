## 1. 프로젝트 개요

### 1.1 목적

행사 참석자들이 모바일/PC에서 행사 페이지에 접속하여 다음 네 가지 기능을 이용할 수 있는 웹앱을 구축한다.

1. **초대 영상 시청**
2. **본인 좌석 확인** (티켓 구매자 대상)
3. **공연 브로셔 열람** (이미지 8장)
4. **출연자에게 응원 메시지 보내기** (닉네임 + 한 줄 응원, 즉시 공개)

### 1.2 타깃 사용자

| 사용자 그룹 | 인원(예상) | 주요 사용 시나리오 |
|---|---|---|
| **일반 관객** | 약 500~700명 | 행사 전 영상 확인, 행사 당일 자리 찾기, 브로셔 열람 |
| **관리자 (운영진 1명)** | 1명 | 좌석 명단 CSV 업로드, 브로셔 이미지 업로드, 좌석배치도 이미지 업로드, 응원 메시지 모더레이션 |

### 1.3 디자인 컨셉

- **톤**: 럭셔리 / 클래식 음악회의 격조
- **컬러**: 먹빛 배경(#0a0a0c) + 와인색(#5c1a1b) + 골드(#c5a572)
- **폰트**: Cormorant Garamond (영문 세리프), Noto Serif KR (국문 세리프)
- **반응형**: 모바일 우선 설계, PC도 동일하게 지원

## 2. 사용자 화면 구성

### 2.1 메인 페이지 (랜딩 페이지)

행사 페이지 접속 시 보이는 첫 화면.

#### 상단 구성
- **헤더**: 행사명(어울림 콘서트), 일시, 장소, 시간 표시
- **초대 영상**: 페이지 안에서 바로 재생되는 유튜브 임베드
  - 영상 URL: `https://www.youtube.com/watch?v=0aT4IdHXZW8`
  - 새 창/팝업 금지 → 페이지 내 인라인 재생
  - 썸네일 클릭 시 자동 재생 방식 권장

#### 메뉴 구성 (2개 카드)
1. **자리 찾기** → 자리 찾기 페이지로 이동
2. **브로셔** → 브로셔 페이지로 이동

#### 관객 콘텐츠 미리보기 영역
- 메뉴 카드 하단에 **3-탭 인라인 미리보기** (`응원 메시지` / `관람 후기` / `사진`)
- 상단 네비게이션: **칩 탭 3개** (클라이언트 상태, 페이지 이동 없음 — v1.4 변경)
  - 활성 탭은 `bg-cream-100 + line border + text-ink` + `aria-selected="true"`. 비활성 탭은 muted 톤
  - 클릭 시 같은 자리에서 콘텐츠가 즉시 전환됨 (URL은 그대로 `/`). 본 페이지(SCR-G04)의 URL-영속 탭과 달리 홈은 **로컬 상태**만 — 새로고침 시 디폴트 탭으로 돌아감
  - **디폴트 탭은 `사진`** (v1.6 변경, 이전: 응원 메시지). 공연 진행 중 실시간으로 올라오는 사진을 첫 방문자에게 곧장 노출 — 현장감이 가장 직접적인 콘텐츠
- 탭별 미리보기 콘텐츠:
  | 탭 | 미리보기 | CTA 버튼 | "전체 보기" |
  |---|---|---|---|
  | 응원 메시지 | 최신 **3건** 카드 (`MessageItem`) | 응원 메시지 보내기 | `/messages` |
  | 관람 후기 | 최신 **3건** 카드 (`ReviewItem compact` — 본문 3줄 line-clamp) | 관람 후기 남기기 | `/messages?tab=review` |
  | 사진 | 최신 **6장** 썸네일 3열 그리드 (라이트박스 없는 server-rendered 미리보기 — 홈 JS bundle 가볍게 유지) | 사진 올리기 | `/messages?tab=photos` |
- "전체 보기" 링크는 탭에 맞는 `?tab=...` 쿼리로 자동 분기. 사진 썸네일을 직접 누르면 같은 링크로 이동(라이트박스는 갤러리 풀 페이지에서만)
- 탭별 카운트는 칩 라벨 옆에 노출하지 않음 (티저답게 깔끔하게). 카운트 노출은 `/messages` 본 페이지의 역할
- 콘텐츠가 0건인 탭은 "첫 N을 남겨 주세요." / "첫 사진을 올려 주세요." 안내 + CTA 버튼만. 칩은 항상 모두 노출

#### 푸터
- 주최: (사)한국예술가곡총연합회

### 2.2 자리 찾기 페이지

#### 2.2.1 핵심 기능

**티켓을 구매한 사람만** 본인의 좌석을 확인할 수 있는 기능.

#### 2.2.2 화면 구성 (상단 → 하단 순서)

1. **헤더**: 뒤로가기 버튼 + "자리 찾기" 타이틀
2. **안내 문구**: "이름과 전화번호 뒷자리 4자리를 입력하시면 좌석을 안내해 드립니다"
3. **검색 입력 영역**
   - 입력 필드 1: **이름** (텍스트)
   - 입력 필드 2: **전화번호 뒷자리 4자리** (숫자 4자리, maxlength=4)
   - 검색 버튼: "자리 확인"
4. **검색 결과 영역** (검색 후 노출)
   - 표시 항목: 이름 / 전화번호 뒷자리 / 좌석번호 (예: A-2)
   - 미일치 시: "일치하는 정보를 찾을 수 없습니다" 안내
5. **전체 좌석 배치도** (하단 고정 영역)
   - 좌석배치 **이미지**를 그대로 표시 (인터랙티브 X)
   - 핀치 줌, 확대보기는 허용 (모바일 사용성)
   - 이미지는 관리자가 업로드한 정적 자산으로 운영

#### 2.2.3 검색 로직

```
검색 조건 (AND 조건, 둘 다 일치해야 결과 노출):
  - 이름이 정확히 일치 (공백 trim, 대소문자 무관)
  - 전화번호 뒷자리 4자리가 정확히 일치
```

**보안 의도**: 이름만으로 검색하면 동명이인 노출 위험이 있고,
타인의 자리를 조회할 수 있으므로 전화번호 뒷자리를 추가 인증 키로 사용한다.

#### 2.2.4 결과 표시 예시

```
✦ 좌석 안내 ✦

이름:       홍길동
연락처:     ****-****-1234
좌석번호:   A-2
```

#### 2.2.5 검색 실패 케이스

| 케이스 | 메시지 |
|---|---|
| 이름은 있으나 전화번호 미일치 | "일치하는 정보를 찾을 수 없습니다. 입력 정보를 확인해 주세요." |
| 이름 미존재 | 동일 메시지 (보안상 "이름 없음"으로 특정하지 않음) |
| 입력값 누락 | "이름과 전화번호 뒷자리 4자리를 모두 입력해 주세요." |

### 2.3 브로셔 페이지

#### 2.3.1 핵심 기능

관리자가 업로드한 **브로셔 이미지 8장**을 순서대로 보여준다.

#### 2.3.2 화면 구성

1. **헤더**: 뒤로가기 버튼 + "브로셔" 타이틀
2. **이미지 뷰어**
   - 8장의 브로셔 이미지를 **세로 스크롤** 방식으로 순서대로 표시
   - 이미지 사이에 페이지 번호 표시 (예: "1 / 8")
   - 모바일에서 확대 보기 가능 (이미지 탭 시 풀스크린)
   - 페이지 사이 적절한 여백 (구분선 또는 골드 ornament)

#### 2.3.3 이미지 표시 방식 옵션

| 방식 | 설명 | 권장 여부 |
|---|---|---|
| **세로 스크롤** | 위에서 아래로 8장이 연속 표시 | ✓ **권장** (모바일 친화적, 직관적) |
| 좌우 스와이프 | 한 장씩 넘기는 캐러셀 | 가능 (구현 복잡도 ↑) |
| 썸네일 + 클릭 확대 | 작은 목록 → 클릭 시 큰 이미지 | 비권장 (이미지 8장 정도면 불필요) |

#### 2.3.4 이미지 최적화

- 업로드 시 자동 최적화 (가로 1600px로 리사이즈, JPG 압축 80%)
- 첫 로딩 시 모든 이미지 한꺼번에 받지 않도록 **Lazy Loading** 적용
- 이미지 캡션은 표시하지 않음 (브로셔 자체에 모든 정보 포함됨)

### 2.4 관객 콘텐츠 페이지 (응원 메시지 / 관람 후기 / 사진)

#### 2.4.1 핵심 기능

관객이 (1) 출연자에게 짧은 한 줄 응원을 남기고, (2) 공연 후 감상을 자유롭게 후기로 작성하며, (3) 공연 현장에서 찍은 사진을 공유할 수 있는 **3-탭 관객 콘텐츠 게시판**. 댓글·좋아요·답글은 모두 제공하지 않는다.

#### 2.4.2 화면 구성 (상단 → 하단)

1. **헤더**: 뒤로가기 버튼 + "응원 메시지" 타이틀 (Chapter III) — 기존 라우트 `/messages` 유지
2. **탭 네비게이션** (3개): `응원 메시지` / `관람 후기` / `사진` (**디폴트 활성, v1.6 변경**). 활성 탭은 burgundy 언더라인. 탭 상태는 URL `?tab=cheer|review|photos` 로 영속 (직접 링크 가능). **canonical URL `/messages` (no `?tab=`) = 사진 탭** (디폴트). `/messages?tab=cheer`, `/messages?tab=review` 는 명시적 진입
3. **(응원 메시지 탭)** 카운트 안내 + Hero CTA 작성 버튼 + 카드 리스트 (최대 100건, 닉네임·KST 날짜·본문). 닉네임 2–10자, 본문 1–200자
4. **(관람 후기 탭)** 카운트 안내 + Hero CTA "관람 후기 남기기" + 카드 리스트 (최대 100건). 닉네임 2–10자, 본문 1–**500자**. 응원과 디자인 톤 동일하되 카드 본문 줄 수 제한 없음
5. **(사진 탭)** 카운트 안내 + Hero CTA "사진 올리기" + **3열 그리드 갤러리** (모바일 3열). 카드 탭 시 라이트박스(yet-another-react-lightbox). 닉네임 2–10자, 캡션 0–100자(선택). 한 번에 최대 3장 업로드

#### 2.4.3 작성 다이얼로그 — 응원 메시지

- 닉네임 2–10자, 본문 1–200자 (줄바꿈 허용, whitespace-pre-wrap)
- 제출 시 즉시 공개. 별도 모더레이션 큐 없음 (사후 삭제만)

#### 2.4.4 작성 다이얼로그 — 관람 후기

- 닉네임 2–10자, 본문 1–500자 (줄바꿈 허용)
- 제출 시 즉시 공개

#### 2.4.5 업로드 다이얼로그 — 사진

- 닉네임 2–10자, 캡션 0–100자(선택), 사진 1–3장 (JPG/PNG/HEIC)
- 클라이언트 + 서버 2단계 압축 (NFR-12 신설). 자세한 사양은 §4.3
- 위치정보(EXIF GPS) 자동 제거
- 제출 시 즉시 공개

#### 2.4.6 도배·악용 방지 (탭별 Rate Limit)

| 탭 | Rate Limit / IP | 사유 |
|---|---|---|
| 응원 메시지 | **1분 1회** | 짧은 한 줄, 즉시성 우선 |
| 관람 후기 | **5분 1회** | 정성스러운 글 유도, 봇 방지 |
| 사진 | **1분 10회 (1회당 1–3장)** | 공연 진행 중 실시간 다량 업로드 허용. 최악의 경우 분당 30장 — 압축 후 평균 400KB라 분당 ~12MB로 Blob 한도 영향은 미미. v1.5 변경 (이전: 10분 1회) |

- IP 는 Rate Limit 키로만 사용하고 저장하지 않는다 (NFR-09)
- 부적절한 글/사진은 운영자가 `/admin/messages` 의 3-탭 모더레이션 화면에서 사후 삭제
- 사진 삭제 시 Vercel Blob 객체도 즉시 함께 제거

#### 2.4.7 실패 케이스 (탭 공통)

| 케이스 | 메시지 |
|---|---|
| 닉네임 길이 위반 | "닉네임은 2–10자여야 합니다." |
| 응원 본문 길이 위반 | "메시지는 1–200자여야 합니다." |
| 후기 본문 길이 위반 | "후기는 1–500자여야 합니다." |
| 사진 0장 또는 4장 이상 | "사진은 1–3장 사이로 올려 주세요." |
| 사진 MIME 거부 | "JPG/PNG/HEIC 만 업로드할 수 있어요." |
| 사진 압축 후에도 4MB 초과 | "사진이 너무 큽니다. 다시 시도해 주세요." |
| Rate Limit 초과 | "잠시 후 다시 시도해 주세요. (N분에 1회만 가능)" |
| 네트워크 / 서버 오류 | "네트워크 오류가 발생했습니다." (재시도 가능) |

## 3. 관리자 기능 (운영자 1인용)

### 3.1 접근 방식

- **URL**: `/admin`
- **로그인 없음** — 운영자 1인이 단독 사용하므로 인증 절차 생략
- **보안 권고**: URL은 외부에 공개하지 않고 운영자만 공유 (Security by Obscurity)
- **선택 옵션** (필요 시): URL에 추측 어려운 문자열 추가 (예: `/admin-h7k9x2`)

### 3.2 관리자 페이지 구성

관리자 영역은 상단 탭 2개로 분리된다:

- **콘텐츠 관리** (`/admin`) — 세 가지 업로드 영역 (CSV / 좌석배치도 / 브로셔 8장) 을 한 화면에 배치
- **응원 메시지 관리** (`/admin/messages`) — 관객이 남긴 응원 메시지 목록과 삭제 (§3.6)

콘텐츠 관리 페이지는 다음과 같이 한 화면에 배치한다.

```
┌─────────────────────────────────────────┐
│  관리자 페이지                           │
├─────────────────────────────────────────┤
│                                          │
│  [1] 좌석 명단 (CSV)                     │
│      현재 등록: 547명                    │
│      마지막 업데이트: 2026-05-25 18:30   │
│      [CSV 파일 선택]  [업로드]            │
│                                          │
├─────────────────────────────────────────┤
│                                          │
│  [2] 좌석 배치도 (이미지 1장)            │
│      [현재 이미지 미리보기]              │
│      [이미지 선택]  [업로드]              │
│                                          │
├─────────────────────────────────────────┤
│                                          │
│  [3] 브로셔 이미지 (8장)                 │
│      [페이지 1] [페이지 2] ... [페이지 8]│
│      [이미지 8장 일괄 업로드]            │
│      또는 [개별 업로드]                  │
│                                          │
└─────────────────────────────────────────┘
```

### 3.3 기능 1: 좌석 명단 CSV 업로드

#### 3.3.1 업로드 흐름

```
1. 관리자가 CSV 파일을 준비 (구글 시트나 엑셀에서 CSV로 내보내기)
2. 관리자 페이지에서 "CSV 파일 선택" → 파일 선택
3. 미리보기 (상위 5~10행 표시)
4. "이 데이터로 덮어쓰기" 확인 버튼
5. 기존 데이터 전체 교체 (overwrite)
6. 업로드 결과 표시: "총 N건 등록 완료" / 오류 행 안내
```

#### 3.3.2 CSV 포맷 명세

| 컬럼 | 필수 | 타입 | 예시 | 설명 |
|---|---|---|---|---|
| `name` | ✓ | string | 홍길동 | 참석자 이름 |
| `phone_last4` | ✓ | string (4자리 숫자) | 1234 | 전화번호 뒷 4자리 |
| `seat` | ✓ | string | A-2 | 좌석번호 |
| `note` | ✗ | string | 임원석 | 비고 (선택) |

**예시 CSV:**
```csv
name,phone_last4,seat,note
신귀복,1234,A-1,이사장석
정희준,5678,A-2,명예이사장석
홍길동,9012,B-5,
```

#### 3.3.3 업로드 시 검증 규칙

| 검증 | 처리 |
|---|---|
| 필수 컬럼 누락 | 업로드 거부 + 오류 메시지 |
| `phone_last4`가 4자리 숫자가 아님 | 해당 행 무시 + 오류 목록 표시 |
| 동일 (이름 + 전화번호) 중복 | 마지막 행 기준으로 저장 (덮어쓰기) |
| 빈 행 | 무시 (skip) |
| 인코딩 오류 (한글 깨짐) | UTF-8 / EUC-KR 자동 감지 시도, 실패 시 안내 |

#### 3.3.4 수정 업로드

- **수정도 동일하게 CSV 전체 교체 방식**
- 부분 수정 UI 제공하지 않음 (요구사항 단순화)
- 업로드 직전 "기존 데이터가 모두 삭제되고 새 데이터로 교체됩니다" 경고 표시
- **백업**: 업로드 시 직전 데이터를 자동 백업 (최근 3개 버전 유지 권장)

### 3.4 기능 2: 좌석배치도 이미지 업로드

- **단일 이미지 1장** 업로드
- 지원 포맷: JPG, PNG
- 권장 크기: 가로 1200px 이상, 용량 5MB 이하
- 업로드 시 기존 이미지 자동 교체
- 업로드 후 미리보기 표시

### 3.5 기능 3: 브로셔 이미지 업로드 (8장)

#### 3.5.1 업로드 방식

**다중 업로드 지원** — 한 번에 8장을 선택하여 업로드 가능.

```
[방식 A: 일괄 업로드]
- "브로셔 이미지 선택" 버튼 클릭
- 파일 선택창에서 8장 모두 선택 (Shift+클릭, Cmd+A 등)
- 파일명 순서대로 자동 정렬 (예: 01.jpg, 02.jpg ... 또는 KakaoTalk_01.jpg ~ _08.jpg)
- 미리보기로 순서 확인
- 필요 시 드래그로 순서 변경
- "업로드" 버튼 → 8장 모두 저장

[방식 B: 개별 업로드 (수정용)]
- 각 페이지(1~8번) 슬롯이 표시됨
- 슬롯별로 개별 교체 가능 (예: 3페이지만 교체)
```

#### 3.5.2 처리 규칙

| 항목 | 사양 |
|---|---|
| 지원 포맷 | JPG, JPEG, PNG |
| 최대 매수 | 8장 (8장보다 적게 올려도 가능, 초과 시 거부) |
| 최대 용량 | 장당 10MB |
| 자동 최적화 | 가로 1600px로 리사이즈, JPG 압축 80% 적용 |
| 순서 | 파일명 오름차순 자동 정렬 → 수동 재배치 가능 |
| 기존 이미지 | 새로 업로드 시 전체 교체 (덮어쓰기) |

#### 3.5.3 미리보기

업로드 전 8장의 썸네일을 격자(grid)로 표시하고, 페이지 번호를 매겨 사용자가 순서를 확인할 수 있게 한다.

```
┌──────┬──────┬──────┬──────┐
│  1   │  2   │  3   │  4   │
└──────┴──────┴──────┴──────┘
┌──────┬──────┬──────┬──────┐
│  5   │  6   │  7   │  8   │
└──────┴──────┴──────┴──────┘
[순서가 맞으면 "업로드" 클릭]
```

### 3.6 기능 4: 관객 콘텐츠 모더레이션 (`/admin/messages`)

#### 3.6.1 화면 구성

- 상단 헤더 "관객 콘텐츠 관리" + 안내문 "관객이 보낸 응원 메시지·후기·사진을 확인하고 부적절한 항목은 삭제합니다."
- **3-탭 네비게이션**: `응원 메시지` / `관람 후기` / `사진`. 각 탭 상단에 카운트 노출 (예: "총 N개")
- (응원/후기 탭) 카드 리스트 — 닉네임, 본문, 작성 시각, **삭제 버튼**
- (사진 탭) 그리드 — 썸네일, 닉네임, 캡션, 업로드 시각, **삭제 버튼**

#### 3.6.2 삭제 흐름

1. 카드의 "삭제" 버튼 클릭
2. 확인 모달 ("이 항목을 삭제할까요? 되돌릴 수 없습니다.")
3. 확인 시 해당 엔드포인트 호출:
   - 응원: `DELETE /api/admin/messages/[id]`
   - 후기: `DELETE /api/admin/reviews/[id]`
   - 사진: `DELETE /api/admin/photos/[id]` — DB row 제거 + Vercel Blob 객체 함께 제거
4. 성공 시 카드가 목록에서 사라지고 카운트 1 감소
5. 홈 미리보기 / 공개 `/messages` 모두 즉시 반영 (`revalidatePath`)

#### 3.6.3 비공개·복구 미지원

- 일시 비공개·복구 기능은 제공하지 않는다 (요구사항 단순화)
- 삭제는 hard delete (DB row + Blob 객체 동시 제거)
- 부적절 콘텐츠 신고(reporting) UI 도 없음 — 운영자 1인이 직접 목록을 훑어 판단

## 4. 기술 사양

### 4.1 권장 기술 스택

#### 옵션 A: 가장 간단한 구성 (운영비 최소)

- **프론트엔드**: 정적 HTML + CSS + JavaScript (현재 만들어둔 페이지 활용)
- **백엔드**: Google Sheets + Apps Script (DB 대용)
- **이미지 저장**: Cloudinary 무료 티어
- **호스팅**: Netlify / Vercel / GitHub Pages (무료)
- **장점**: 무료, 유지보수 쉬움
- **단점**: 동시접속 매우 많을 때 일부 지연 가능

#### 옵션 B: 정식 백엔드 구성 — **채택**

- **프론트엔드**: Next.js 15 (React 19, App Router)
- **백엔드**: Next.js API Routes (Vercel Functions / Fluid Compute)
- **DB (production)**: **Neon Postgres** (Vercel Marketplace 통합, Free Tier — 10 프로젝트, auto-suspend + 자동 wake)
- **DB (local dev/test)**: PostgreSQL 로컬 설치 (Homebrew)
- **이미지/파일 저장**: **Vercel Blob** (Hobby Free Tier — 1 GB, public bucket)
- **호스팅**: Vercel
- **장점**: 확장성, 정식 관리자 UI, 단일 벤더(Vercel)에서 통합 관리, "1 행사 = 1 Neon 프로젝트" 자연스러운 격리
- **단점**: 초기 구축 시간 더 필요
- **이력**: 2026-02-27 — 기존 Supabase (DB + Storage) 조합에서 Neon + Vercel Blob로 마이그레이션. 사유: Supabase Free Tier 7일 자동 pause 사고 발생 + Supabase Free 2-프로젝트 제한이 단발성 행사 다수 운영에 부적합. Neon은 10 프로젝트 무료 + cold wake-up 자동.

### 4.2 데이터 저장 구조

운영 테이블은 **5개** (`attendees`, `assets`, `messages`, `reviews`, `photos`) + 선택 백업 1개 (`csv_backups`).

**테이블 1: `attendees` (좌석 명단)**

| 필드 | 타입 | 비고 |
|---|---|---|
| id | int (auto) | PK |
| name | string | 인덱싱 |
| phone_last4 | string(4) | 인덱싱 |
| seat | string | 예: "A-2" |
| note | string (nullable) | |
| created_at | timestamp | |
| updated_at | timestamp | |

**테이블 2: `assets` (이미지 자원)**

| 필드 | 타입 | 비고 |
|---|---|---|
| key | string | "seat_map", "brochure_01" ~ "brochure_08" |
| url | string | 이미지 URL |
| updated_at | timestamp | |

**테이블 3: `messages` (응원 메시지) — ENT-04**

| 필드 | 타입 | 비고 |
|---|---|---|
| id | cuid | PK |
| nickname | varchar(10) | 닉네임 2–10자 |
| body | varchar(200) | 본문 1–200자 |
| created_at | timestamp | 인덱스 (DESC) |

**테이블 4: `reviews` (관람 후기) — ENT-05**

| 필드 | 타입 | 비고 |
|---|---|---|
| id | cuid | PK |
| nickname | varchar(10) | 닉네임 2–10자 |
| body | varchar(500) | 본문 1–500자 |
| created_at | timestamp | 인덱스 (DESC) |

**테이블 5: `photos` (사진) — ENT-06**

| 필드 | 타입 | 비고 |
|---|---|---|
| id | cuid | PK |
| nickname | varchar(10) | 닉네임 2–10자 |
| caption | varchar(100) (nullable) | 캡션 0–100자 (선택) |
| url | string | Vercel Blob public URL |
| width | int | 이미지 가로(px) |
| height | int | 이미지 세로(px) |
| byte_size | int | 압축 후 바이트 수 (스토리지 모니터링) |

IP·이메일·전화번호 등 식별자 저장 없음 (NFR-09). EXIF GPS 좌표는 서버 압축 단계에서 자동 strip 되어 저장되지 않는다. 작성자는 사후 자신의 글/사진을 삭제할 수 없으며, 운영자만 `/admin/messages` 의 3-탭 화면에서 삭제한다.

### 4.3 성능 요구사항

| 항목 | 목표 |
|---|---|
| 페이지 첫 로딩 | 2초 이내 (3G 환경에서도 3초 이내) |
| 자리 검색 응답 | 1초 이내 |
| 브로셔 이미지 로딩 | 첫 이미지 1초 이내, 나머지는 Lazy Load |
| 동시 접속 처리 | 최소 100명 동시 사용 가능 |

### 4.4 보안 요구사항

- 관리자 URL은 외부 공개 금지 (운영자만 보관)
- CSV 파일 업로드 시 파일 크기 제한 (5MB 이하)
- 운영자 이미지(좌석배치도/브로셔) 업로드 시 파일 크기 제한 (장당 4MB 이하)
- 관객 사진 업로드: 클라이언트가 1차 압축한 결과만 서버에 전송 — Vercel Functions 4.5MB body 한도 회피
- 검색 시 Rate Limit 적용 (1분당 30회 이내) — 무차별 조회 방지
- 응원 메시지 작성 Rate Limit (1분당 1회 / IP), 후기 (5분당 1회 / IP), 사진 (10분당 1회 / IP) — 도배·스토리지 남용 방지
- 개인정보(전화번호)는 **뒷 4자리만** 사용, 평문 저장 가능 (전체 번호 저장 금지)
- 응원/후기/사진 작성자 식별 정보(IP/이메일/전화)는 저장하지 않는다
- HTTPS 필수

### 4.5 이미지 압축 정책 (NFR-12 신설)

관객이 업로드하는 사진은 **2단계 압축 파이프라인**을 거쳐 저장된다.

| 단계 | 처리 위치 | 파라미터 | 목적 |
|---|---|---|---|
| ① | 클라이언트 (브라우저) | `browser-image-compression`, max 1600px · JPEG quality 80 · 결과 ≤ ~800KB | 업로드 속도, Vercel 4.5MB body 한도 회피 |
| ② | 서버 (Vercel Function) | `sharp`, max 1200px · JPEG quality 75 · `withMetadata: false` (EXIF/GPS strip) | 신뢰성, 위치정보 자동 제거, 최종 용량 정규화 (평균 300–500KB) |

운영자 업로드(좌석배치도·브로셔)는 기존 1단계 (서버 sharp, 1600px·quality 80) 유지 — 단발성 8–9장이라 클라이언트 압축의 이점이 적다.

**스토리지 모니터링**: `photos.byte_size` 합계로 Vercel Blob 사용량 추정. 1GB Free Tier에서 평균 400KB 기준 약 2,500장 수용. 초과 가능성이 보이면 관리자가 사후 삭제로 정리.

## 5. 운영 시나리오 (행사 당일 흐름)

### 5.1 행사 전 (D-7 ~ D-1)

1. 운영진이 티켓 신청자 명단을 정리 (구글 시트 등)
2. 좌석 배치 결정 후 명단에 좌석번호 부여
3. CSV 형식으로 내보내기
4. `/admin` 접속 → CSV 업로드
5. 좌석배치도 이미지 업로드
6. 브로셔 이미지 8장 일괄 업로드
7. 본인 이름으로 검색 테스트 → 정상 동작 확인
8. 브로셔 페이지 → 이미지 8장 모두 정상 표시 확인
9. 행사 페이지 링크를 QR코드로 만들어 안내 자료에 포함

### 5.2 행사 당일

1. 관객이 입장 전 QR코드 스캔 또는 링크 접속
2. 메인 페이지에서 초대 영상 시청
3. **"자리 찾기"** 메뉴 → 이름 + 전화번호 뒷자리 입력 → 좌석 확인
4. 좌석배치도에서 위치 확인 후 입장
5. 좌석 착석 후 **"브로셔"** 메뉴로 공연 정보 열람 (이미지 8장)

### 5.3 명단 수정이 필요한 경우

1. 운영진이 원본 시트 수정
2. 수정된 CSV 재업로드 (기존 데이터 전체 교체)
3. 변경 즉시 반영

### 5.4 브로셔 수정이 필요한 경우

1. `/admin` 접속
2. 수정할 페이지의 이미지 개별 교체 또는 8장 전체 재업로드
3. 변경 즉시 반영

## 7. 명시적으로 제외하는 기능 (Out of Scope)

다음 기능은 본 프로젝트 범위에 포함되지 않는다.

- 티켓 결제 / 발권
- 좌석 선택 (참석자가 좌석을 직접 고르는 기능)
- 회원가입 / 로그인 (일반 사용자용)
- 관리자 로그인 / 권한 관리
- SMS / 알림톡 발송
- 좌석배치도의 인터랙티브 기능 (내 자리 자동 하이라이트 등) — 정적 이미지로 충분
- 브로셔 내용 텍스트 검색
- 다국어 지원 (한국어만)
- 응원/후기/사진의 **좋아요·댓글·답글·신고(report) 기능** — 일방향 게시만
- 응원/후기/사진의 **수정·작성자 본인 삭제 기능** — 운영자만 삭제 가능
- 동영상 게시 — 사진만 지원 (행사 후 영상은 별도 YouTube 링크로 처리)
- 사진의 **관리자 승인 큐** — 즉시 공개 정책, 사후 삭제만 (PRD §2.4.6)
- 사진의 자동 콘텐츠 분류·AI 모더레이션

## 9. 체크리스트 (개발 완료 시 확인할 항목)

### 사용자 페이지
- [ ] 메인 페이지에서 영상이 인라인으로 정상 재생됨
- [ ] 모바일 / PC 양쪽에서 레이아웃이 깨지지 않음
- [ ] 자리 찾기에서 이름 + 전화번호 뒷자리로 정확히 조회됨
- [ ] 검색 실패 시 적절한 안내 메시지가 노출됨
- [ ] 좌석배치도 이미지가 자리 찾기 페이지 하단에 항상 표시됨
- [ ] 브로셔 페이지에서 이미지 8장이 순서대로 정상 표시됨
- [ ] 브로셔 이미지가 모바일에서 확대 보기 가능함
- [ ] 브로셔 이미지 Lazy Loading 동작 (스크롤 시 순차 로드)
- [ ] 홈에 최근 응원 메시지 3건이 미리보기로 노출됨
- [ ] `/messages` 에서 응원 메시지 작성·즉시 공개가 정상 동작함
- [ ] 1분 내 2번째 작성 시 Rate Limit 안내가 표시됨

### 관리자 페이지
- [ ] `/admin` 접속 시 별도 로그인 없이 바로 페이지 표시
- [ ] CSV 업로드 시 미리보기가 표시됨
- [ ] 잘못된 포맷 CSV 업로드 시 오류가 안내됨
- [ ] 기존 명단을 새 CSV로 덮어쓰기가 정상 동작함
- [ ] 좌석배치도 이미지 교체가 정상 동작함
- [ ] 브로셔 이미지 8장 일괄 업로드가 정상 동작함
- [ ] 브로셔 이미지 개별 교체가 정상 동작함
- [ ] 업로드 직전 데이터가 자동 백업됨
- [ ] `/admin/messages` 에서 부적절 메시지 삭제 시 홈 미리보기·`/messages` 양쪽에 즉시 반영됨

### 성능 / 보안
- [ ] 페이지 로딩이 3초 이내
- [ ] HTTPS로 접속됨
- [ ] CSV / 이미지 파일 크기 제한이 적용됨
- [ ] 검색 Rate Limit이 적용됨
